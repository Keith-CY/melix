# Evaluation Parameter Map Binding Slice

## Scope

This Python-only performance slice is limited to `EvaluationCore.run_local_suite()` in `services/mlx-worker-python/worker/engine/evaluation_core.py`.

The optimization preserves evaluation behavior while binding `parameters or {}` once per run and reusing that map for default scoring mode, code-execution policy, task-kind resolution, event-extraction dispatch, and persisted job-parameter initialization. This removes repeated fallback-map allocation/truthiness checks on the hot local-suite setup path.

## Registered performance probe

The affected source path is already covered by the registered `evaluation-sample-probe-aggregation` and `evaluation-job-id-high-water-mark` PR-scoped probes in `infra/perf/pr_scoped_probes.json`. Those entries include focused `test_command`, `coverage_command`, and `probe_command` fields. This slice extends the `evaluation-sample-probe-aggregation` focused test and coverage commands with the new parameter-map regression and the existing event-extraction compare branch coverage so the registered probe remains a valid gate for the touched lines.
